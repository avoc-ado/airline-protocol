# Airline Protocol V1 - Build Specification

This document turns the initial high-level requirements into a concrete, actionable build plan so multiple agents can work in parallel with minimal ambiguity.

## Goal
Create a Jet V1-inspired lending and borrowing protocol on Solana, with a local validator, on-chain program, rich web UI, and a fully tested Typescript client + CLI. All major architecture decisions should mirror Jet V1, while the UI and branding are distinct but clearly inspired by Jet V1.

## Reference
- Primary reference repo (cloned locally): `airline-protocol/vendor/jet-v1`
- Notes on the reference repo: `airline-protocol/docs/jet-v1-reference.md`

## Core architecture (must-have)
- On-chain program written with Anchor (Rust)
- Local test validator with Serum DEX preloaded (genesis) and Pyth price oracles
- Migration script that initializes market, reserves, and writes IDL metadata used by the UI
- Next.js frontend that talks directly to RPC (no backend) and loads IDL metadata in-browser
- Typescript CLI covering all protocol actions (deposit, borrow, repay, liquidate, etc.)
- Strong code-sharing between CLI and frontend via shared packages
- Comprehensive tests (unit + integration + e2e) with 85% unit test coverage
- Parallel-safe integration tests (no port collisions across agents)

## On-chain program
Model after Jet V1 program structure:
- Instructions: init market/reserve, update reserve config, init user accounts, deposit/withdraw, deposit/withdraw collateral, borrow/repay, liquidate, refresh reserve
- State accounts: market, reserve, obligation, cache
- Uses Pyth price data and Serum DEX (for liquidation routes)

## Localnet and migration
- Start a local validator with Serum DEX as a preloaded program (genesis entry)
- Build + deploy the program via Anchor
- Migration script should:
  - Create test mints (at least USDC, SOL, BTC, ETH equivalents)
  - Create Pyth price + product accounts and set deterministic prices
  - Create Serum markets per asset vs. the quote token
  - Initialize the market and reserves
  - Write IDL metadata to a web-consumable JSON file (for the UI)

## Shared Typescript packages
Create a shared package (or packages) used by both CLI and frontend:
- IDL metadata parsing
- RPC connection setup and program client
- Account PDA helpers
- Core models (market, reserve, obligation, user balances)
- Transaction builders and instruction helpers

## Typescript CLI
A rich CLI for all protocol functionality. Minimum scope:
- Market: read, initialize, set flags, list reserves
- Reserve: init, update config, refresh, read stats
- User: deposit, withdraw, deposit collateral, withdraw collateral, borrow, repay
- Liquidation flows
- Diagnostics: fetch account state, compute health factors, validate configs

CLI must have integration tests that run against localnet.

## Frontend (Next.js)
- Direct RPC access in browser (no backend server required for protocol actions)
- Loads IDL metadata generated by migration
- Views that mirror Jet V1 capabilities:
  - Dashboard / cockpit view of reserves
  - Per-reserve detail and trade panel
  - User position and health indicators
  - Transaction logs / activity
  - Settings / RPC node selection
- Strong UX with clear data visualization (rates, utilization, health factors)

## Branding
- Distinct, original name and assets (Airline Protocol), but clearly inspired by Jet V1 style
- Jet-like gradients, bold typography, and dashboard feel are acceptable
- Do NOT copy logos or exact art assets from Jet; create new ones that feel like a deliberate homage

## Testing requirements
- Unit tests for program logic, shared libs, and CLI utilities
- Integration tests against localnet covering end-to-end flows
- E2E browser tests with Playwright for core user journeys
- Enforce >= 85% unit test coverage
- Tests should run after every change (CI + local enforcement)

### Parallel test strategy (no port collisions)
Multiple agents may run tests on the same machine. Requirements:
- Use random or isolated ports for:
  - Solana test validator RPC and WS
  - Next.js dev server
  - Any local services used by tests
- Use a deterministic but isolated port strategy per test worker, for example:
  - Base port + worker index offset
  - Or allocate free ports at runtime (e.g., `get-port`)
- Ensure tests clean up any localnet processes they start

## UI validation workflow
Any UI-affecting change must be verified using Chrome DevTools:
- Load the UI locally
- Check layout, typography, spacing, and interaction states
- Confirm responsiveness (desktop + mobile breakpoints)
- Document any UI regressions and fix before merging

## Documentation expectations
- Keep `docs/airline-protocol-v1.md` as the authoritative spec
- Add implementation notes as new docs when needed
- Update `docs/jet-v1-reference.md` when new findings are discovered

## Acceptance criteria
- Localnet can be started with one command, fully configured with reserves and IDL metadata
- CLI can perform all core actions against localnet
- Next.js UI can connect to localnet and execute core flows
- Unit test coverage >= 85%
- Integration tests and Playwright e2e tests pass reliably in parallel
- Branding is clearly Jet-inspired but original and distinct
